# 栖卷 Windows 产品路线

目标是覆盖 Fileway Web 与 Android **已存在且未被用户明确排除的用户功能并集**，并提供合适的
Windows 原生交互。不是把 Go 接口存在、播放器引擎支持或页面按钮出现当作完成。
Android 的 SAF、前台通知与 APK 安装等平台机制，在 Windows 上以文件选择器、
原生任务/通知及安装升级等对应能力实现。

用户已明确排除 Windows 的分享与公共分享能力：不实现分享创建/管理/链接，也不实现公共分享
接收/密码/下载；这些不进入 0.7 或 1.0 完成清单。Web 与 Android 已有能力保持，不修改其他平台。

手动文件校验和功能也已由用户排除：移除工具菜单和文件右键入口，不再为其安排后续版本或原生验收。
已有实现及旧测试记录仅为历史，不构成当前交付要求。传输内部的数据完整性校验继续保留。

0.2.5 起统一动效按 [原生动效规格](ui-motion.md) 推进，以连续、自然、可中断为目标。
手动原生体验验收由用户执行；开发负责代码、必要构建与风险相关的契约验证，未由用户确认的体验不标为通过。

0.2.6 的开发切片已接入 NAS 搜索结果和文件任务原生页面：搜索支持当前目录/含子目录与流式结果，
任务支持筛选、分页、详情、操作确认及持久记录核实；这两项不再记为只有控制器。0.2.6 已生成本地未签名测试包，
人工体验及后续回收站、剪贴板和浏览偏好缺口继续保留，播放器退出 CFG 问题独立优先跟踪。

## 版本规则

- 使用普通增量版本 `0.2.0`、`0.2.1`、`0.2.5` 等；小版本既可增加功能，也可修复问题，
  不再使用 `preview.n` 作为新版本编号。`0.2` 等分组仍表示产品方向，不要求每次发包完成整组。
  未完成的功能不因版本号提高而自动算作已交付；未签名、本地开发包状态独立标明。
- 每个里程碑允许多个可运行预览，但必须通过本版本的完整旅程才关闭里程碑。
- 已验收的 Screenbox 风格播放器是视觉基线，现有交互保留并按功能另行验收；后续增量扩展，不能推倒重做。
- 播放器验收不等于文件浏览器、传输中心及其他页面已通过视觉验收。
- 文件浏览器已选择 A「清晰 Fluent」：参考 Files，与现有 Screenbox 风格统一；原生代表性切片仍须验收。
- 近期以功能旅程为主，A 方向的明暗主题、清晰度和基本视觉质量仍是当期门槛。
  B「栖卷书房」与 C「影音工作台」保留为后期多风格主题候选，排入 0.8，暂不并行实现。
  明暗模式是同一方向的显示方式，不等于三种不同视觉风格。
- 所有应用窗口使用统一无边框、自绘标题栏，保留必要的原生窗口交互与阴影/圆角。
  Windows 图标保留 Android 品牌矢量，独立放大主体并使用透明圆角背景，适配桌面尺寸。
- 下面的版本归属是交付顺序，不是所有模块必须串行开发的要求。
- 新增、取消或移期功能必须同时修改该表与对应能力状态，保留原因和依赖。
- 验证按真实改动及风险选择，避免每个小版本重复无关全量测试；共享契约、权限、数据与恢复
  保留聚焦回归，候选版继续完成整个目标要求的完整验收。

## 0.1 已有能力与边界

当前已有：临时账号密码/免认证连接、系统网络直连（包括系统 Tailscale 路由）、
目录列表及返回/上级/刷新/取消、五种排序、当前已加载目录的名称过滤、基础详情；
原生图片查看/前后张/缩放；libmpv 原生视频、暂停/seek/音量/静音、全屏、章节、
内封字幕/音轨、本地外挂字幕、按格式开放的字幕样式、自定义倍速、服务器进度与续播；
完整本地媒体文件可通过启动参数离线打开。程序使用 Android 同源品牌图标。

仍没有：持久连接和凭据、服务器搜索、缩略图/网格、新建/改名/复制移动/回收站、
上传下载/任务中心、音频入口、服务器外挂字幕、雪碧图、跨文件选集、HLS 画质切换、
文档编辑/分享/管理等。源分辨率单项显示不是多画质，章节不是选集；当前目录过滤不是
远端递归搜索。服务端续播与字幕/格式组合仍须用实际服务器和样本验收。

此批功能改用普通版本号 **0.2.0** 交付，后续使用 `0.2.x` 增量。

## 最新跨端变化的具体落点

主线快照 `67853b2f` 的增量已核对；这些是对齐要求，不表示 Windows 已实现或已合并主线。

- **0.2 登录恢复**：按认证拒绝、权限拒绝、网络/组网、本地凭据/数据库及未知阶段分类反馈；
  诊断不输出原始私密错误。续期后更新同一 userId 的 claims/用户名/权限再保存与激活。
  对 renew401 的分类保持共享核心严格边界：不把403/503/断流/非法token变成密码恢复，
  不重放操作，已确认成功写入不得丢失。
- **0.4 字幕**：列出已安装系统字体、默认/跟随系统与失效回退；文本字幕可选择画面内或
  包含黑边的播放区域，黑色背景0—100%且默认透明，支持预览/重置/设备保存。
  切区域不改变视频尺寸或字幕字形；ASS/SSA作者样式、位图能力边界继续保留。

## 核心依赖与不变约束

### 视频下载与播放的近期优先项

视频下载需要支持下载未完成时进入现有 Screenbox 播放器，并持续展示该下载任务的真实进度。
这项 0.3 下载生命周期与 0.4 播放能力的交叉切片近期并行推进，不等待其他影音扩展全部完成。
参考 Android 的 `DownloadDataSource`、`DownloadIndex` 与 `PlayerScreen`，但保持 Windows 的本地对象
归属、账号/会话隔离和发布验证边界。当前预加载缓存、完整本地文件播放或新增进度文字都不等于
边下边播已经完成。

- 下载输入绑定准确的账号上下文、任务和执行代次；播放器不能重新打开未经验证的 partial 路径。
- 已接收字节/总量与真实百分比独立于播放位置、引擎缓冲区间和上游预加载速度；总量未知时不编造百分比。
- 可读前缀、已 flush 字节、已校验发布分别表示不同证据。接收达到 100% 仍可处于校验或保存阶段。
- 可离线播放时间只在索引及保留数据证据充分时显示，不能把字节占比直接换算成视频时间。
- 播放暂停不暂停下载，后续数据到来不能覆盖手动暂停；关闭播放器释放读取能力，不擅自取消下载。
- 取消下载、源变化、账号退役时唤醒并排空读取，再按既有归属规则处理文件；发布完成不重启当前播放会话。
- 实际验收覆盖未完成前出画、前缀边界等待/继续、已下载和未下载位置的 seek、手动暂停、取消/关闭竞争、
  完成后连续播放，以及前置/尾置索引 MP4 与 MKV。仅前缀读取的切片必须明示尾部索引限制，不能冒充
  Android 的按需 Range 和离线索引能力全部实现。

当前接入仅为仍在运行或校验中的本次下载授予读取能力，本地部分读取同一已持有文件对象的连续前缀。
缺失字节已实现认证的按需 Range 读取：本地前缀优先，远端只使用现有单资源租约；每个读取者
最多保留 1 MiB 内存预读，共最多四个读取者，不写入下载文件或增加保存进度。读取前后复核账号、
权限、任务、执行代次、源长度和完整修改时间，严格验证 206、范围、长度及响应完整性；
这些来源观察不是不可变版本，也不授予断点续传能力。缺少修改时间时保持原有前缀等待行为。
该 Range 模块通过独立审查、358 项相关测试及 WinUI Release/x64 集成构建（0 警告/错误）；真实容器
验收仍待完成，离线媒体时间索引、
历史完成任务重新打开仍未实现。原生解码验证工具采用前置头部的固定 Y4M 合成视频，它不代表 MP4/MKV 全容器支持，
也不替代可见播放器界面的实际验收。读取租约撤销、账号/任务代次失效、停止或退出时，
当前可读前缀立即变为不可用；下载任务的历史接收/写盘证据仍单独保留。读取返回及 EOF 前再次核实
授权，取消先唤醒原生回调，真实 mpv 销毁返回后才释放读取对象。正常校验、发布及同一已持有
文件对象的已完成状态继续可读，不通过重开 partial 路径延长能力。
取消、撤权或账号退役会排空实际本地/网络读取及远端租约释放；该控制流程不等待播放器销毁或窗口关闭，
避免传输先退出、播放器随后退出的应用关闭顺序形成等待环。原生回调仍在真实 mpv 销毁返回后释放。

该生命周期切片通过 419 项受影响托管测试、Windows Release/x64 构建及固定 Y4M 的真实 libmpv
解码验证：未完成前解码、边界等待后继续、手动暂停不被追加覆盖、阻塞读取取消、原生销毁返回、
销毁后释放、关闭读取者后写入继续及新归属读取者可用。验证使用 `vo=null`，尚不证明可见画面、
一般 MP4/MKV、任意 seek 或退出窗口无崩溃；这些 P0 原生门槛继续保留。

身份/能力/本地数据先于写操作与传输；传输任务和不可变资源身份先于边下边播；
媒体质量选项来自真实服务端 HLS 能力，不能生成假的 720p/1080p 菜单。
扩展接口优先使用已有 server/shared-core 契约，新增行为必须向后兼容并有 Android 回归。
Windows 保持 WinUI 3、Go Host 私有 IPC、libmpv、SQLite/DPAPI 的既定边界。

本地路径和远端 wirePath 分离，目录/文件名不经过 Windows 路径归一化改写远端身份。
Delete 显式使用回收站语义；服务端和本地任务分别管理，取消请求接受不等于取消完成。
所有成功/失败/部分成功/冲突/结果未知必须可解释。后台任务、缓存、历史与租约均绑定账号。

不购买签名、不修改 Android 标识、不自动合并 main、不自动改 NAS 生产状态；
不将原有“首版非目标”永久当成 Web/Android 功能的排除理由。
