# 栖卷 Windows 0.8.155

用户实机截图指出「最基本的排版布局对齐都没做好」。这条批评成立：本地服务端页的「标签 | 值 | 操作」网格
有四处系统性对齐缺陷，0.8.152 交付时我只核了按钮右边缘，没有核标签与值的基线关系。本版全部修掉并留下
可复核的数字断言。

## 修了什么

1. **值文本没有垂直基准**（最刺眼的一条）。标签写了 `VerticalAlignment="Center"`，值没写 → 值默认顶对齐。
   只要同一行里有 36 DIP 的按钮把行高撑起来，标签与值就错开半行。实测错位量：
   日志目录行 12px、用户名/密码行 **14px**（150% 缩放下约 9 DIP）。现在标签与值中心差 ≤0.5px。
2. **同类路径行的右边缘不一致**。「数据目录」的值写了 `Grid.ColumnSpan="2"` 跨过操作列，「日志目录」没有，
   于是两行同样长度的路径在不同位置被省略号截断。去掉跨列后五行值右边缘统一（实测同为 1185）。
3. **一行一个按钮与一行两个按钮右边缘不齐**。「用户名」行 1 个复制按钮、「密码」行 2 个按钮，
   操作列是 `Auto` → 两行值的右边缘和按钮右边缘都不同。操作列改为固定 76 DIP（36+4+36）并让按钮右对齐。
4. **两张堆叠卡的值左边缘不齐**。「本机构建」标签列 84、「启动与账号」标签列 64，窄窗口下两卡上下堆叠时
   值的起始位置不一样。统一为 84。
5. **部署卡里 `Margin="0,22,0,0"` 这个凑出来的数字**。密码行原本是「标签+输入框」一个 StackPanel、
   按钮另一个 StackPanel 底部对齐再加 22px 边距 —— 22 是「标签高+间距」的手算值，差 1px 就歪。
   改成两行 Grid（第二行固定 36 DIP），按钮与输入框天然同轴；「文件夹路径」行同样重写，去掉
   `VerticalAlignment="Bottom"` 依赖。
6. **空闲的 ProgressRing 在头部占位**。只把 `IsActive` 设 false 时它仍占 20 DIP，并在标题右侧留下淡色残影
   （用户截图里那个蓝色小弧）。改为 `Visibility="Collapsed"`，头部按钮与标题的间隙从 54px 降到 12px
   （= 8 DIP 的 StackPanel 间距）。

## 验证

- **对齐断言 15 项全通过**（`20261102-server08155/align3/report.txt`，150% 缩放、1290 DIP 宽窗口）：
  五行事实行标签/值中心差 0–0.5px；值右边缘唯一（1185）；用户名/密码行标签值同轴（1142 vs 1142）；
  两行复制按钮右边缘同为 1254 = 卡片内容右边缘；密码行按钮与输入框同轴（639 vs 639）；
  头部环状占位间隙 12px ≤ 21px 上限。
- **实拍 12 张**（浅/深色各 6 张：`shots-light/`、`shots-dark/`）：检测卡 + 部署表单、高级限定共享范围展开、
  已部署宽窗、凭据显示、仅错误日志、1180 窄窗。深色下文字对比与描边正常。
  这是本地服务端页**第一次**拿到真实截图（0.8.152–0.8.154 三轮都因会话锁定只有数值证据）。
- Release x64 构建 0 警告 0 错误；两次启动冒烟 `GATE=PASS`。

## 顺带记录

- 验证期间发现 8888 上又出现了一个 `filebrowser.exe`（PID 7448，非本客户端启动）。按 0.8.154 的单服务端规则，
  客户端如实回显它、拒绝再部署第二个，并把它当作用户已有的服务端提供「连接 / 打开 Web 端」——
  这正是设计意图，不是缺陷。
- 本版未改任何功能行为（仅 XAML 布局 + `SetBusy` 的可见性），0.8.154 的 24 项功能回归与全链路 29 项结论继续有效。

## 已知边界

- 高对比度下的本地服务端页仍未走查。
- 禁用态主按钮仍是淡强调底色填充，视觉上与可用态区分度偏低；是否改为描边/降饱和需要一次设计决策，
  本版不动（避免与对齐修复混在一起）。
- 安装包为本机未签名候选。
