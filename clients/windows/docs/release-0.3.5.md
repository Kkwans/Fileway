# 栖卷 Windows 0.3.5

可靠传输里程碑的 Range 续传增量；本地未签名预览，供用户人工安装验收。

## 本版新增

- 服务端声明 `conditionalDownloadV1` 时，单文件下载从准备阶段起绑定 opaque
  `sourceVersion` 并写入任务快照；旧服务端（无该能力）保持原 fresh-only 语义。
- 断点续传与重启恢复：任务具备 pinned 版本、已确认 flush 偏移与已持有 partial
  128 位文件身份即可续传。恢复先在本任务 OS 锁下把意图翻回 Run，再以 recovery
  claim 围栏上一进程的陈旧 run，重新进入同一 FIFO 单 writer 队列。
- 续传协议：重开 partial 核对身份并截断未确认尾部（同句柄截断）；Range 请求要求
  精确 `206` 与 `Content-Range` 且响应 `X-Fileway-Source-Version` 与 pinned 版本一致；
  对 Range 请求返回 `200` 一律拒绝（不追加）；版本/长度/修改时间变化拒绝续传并清理
  partial；完成校验和绑定同一版本，仍从持有句柄重读全文件 SHA-256。
- 接收期间每 30 秒 flush 并持久化确认偏移，崩溃最多损失一个间隔的已接收字节。
- 失败保留：版本化任务的非取消失败保留 partial 并落入可恢复相位（需要重新登录→
  WaitingAuthentication、网络/超时→WaitingNetwork、其余→Failed 并保留错误信息）；
  显式取消与源变化仍清理 partial；发布不确定路径不变（先本地核实）。
- 退出排空优先挂起：符合条件的执行（含用户已暂停的）持久化 Pause 意图、保留
  partial 与确认偏移后停止；发布中的任务仍走核实路径。退出不再是取消清理。
- 传输中心继续按钮按证据路由：进程内暂停走原暂停控制，其余可恢复任务走持久续传。
- 存储设置新增「连接后自动继续未完成的下载」（SQLite schema 7，默认关闭）；开启后
  每次连接把有持久证据的中断任务批量重新排队，仍受 100 项队列上限约束。

## 边界

- 进程内暂停仍保留原 HTTP 响应与句柄，不是 Range 续传；两者由同一按钮按状态路由。
- 旧服务端任务不获得续传；本地数据库 schema 自动从 6 迁移到 7（自动迁移前有备份）。
- 续传执行期间不提供该 partial 的边下边播读取准入；目录/归档传输、历史完成下载
  重开与完整边下边播保持在 0.3.6/0.3.7 范围。
- 播放器退出 CFG 故障未在本版处理。此前的外部钩子归因已由 2026-10-27 的媒体依赖捕获修正，
  后续 0.8.1 修复与验证见 [当前分析](player-exit-cfg-analysis.md)。

## 验证口径

Release/x64 构建 0 警告 0 错误；本机 UI 预检因 DPI 缩放与 smoke 门槛不兼容未执行，
按用户要求由用户安装后人工验收：真实 NAS 大文件续传、崩溃/退出重启恢复、自动恢复
偏好与旧服务器 fresh 行为。未创建公开 Release/tag，未签名。
