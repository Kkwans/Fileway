# 单文件上传执行

`FileUploadRunner` 把 [上传通道](transfer-transport.md)、[持久任务](transfer-state.md) 和
Windows 文件访问接在一起。它消费已经确认的文件计划，不承担目录枚举、命名决策、队列界面
或启动时自动恢复。显式队列由 `UploadCoordinator` 承担；目录计划、原生界面和自动启动恢复
仍是独立的 0.3 工作。创建执行器、打开数据库不会自动发送请求。

## 执行归属与源文件

`WindowsUploadFileAccess` 同时提供源文件访问和每任务的执行锁。调用者传入明确创建的
应用私有锁目录；它不把任意用户目录变成锁目录，也不递归创建目录。锁使用独占 OS 文件
句柄，跨实例生效，进程退出后释放。SQLite run/generation 负责拒绝迟到结果，不能替代锁。

源文件只读打开，允许兼容的读取，拒绝写入/删除共享；检查目录重解析点、最终句柄路径和
普通磁盘文件类型。逻辑路径保留，扩展路径前缀仅用于 Windows API 边界。设备、备用数据流、
链接跳转和无法证明身份的文件明确失败，不静默跟随或改用另一路径。

祖先目录句柄禁止目录自身被删除/替换，同时允许写入共享，避免误挡同目录其他文件的
原子重命名。共享标志本身不能禁止 FILE_WRITE_ATTRIBUTES，不能宣称它阻止所有原地重解析
修改。各级已打开子目录/源文件/锁文件保持目录非空；锁文件还以已验证末级目录句柄为
根相对创建，拒绝重解析，不沿绝对路径重新跟随刚变化的目录。
[目录共享规则](https://learn.microsoft.com/en-us/openspecs/windows_protocols/ms-fsa/8c0e3f4f-0729-49f4-a14d-7f7add593819)、
[重解析点设置规则](https://learn.microsoft.com/en-us/openspecs/windows_protocols/ms-fsa/4aeefef8-92c3-4abc-af7a-a610caf8a165)
说明这些边界；实际测试覆盖普通 Windows 文件系统行为，不推广到任意第三方过滤驱动。

源快照记录句柄观察到的长度、最后写入时间及卷/文件身份，恢复及分块读取前后复核。
128 位文件 ID 使用 `GetFileInformationByHandleEx(FileIdInfo)`；不是路径哈希，也不把
旧 64 位 ID 的保证推广到 ReFS。[Windows 文件 ID 说明](https://learn.microsoft.com/en-us/windows/win32/api/fileapi/ns-fileapi-by_handle_file_information)
这仍是可观察身份保护，不是文件的不可变历史快照，也不是所有文件系统/网络共享均已验证。

## 协议与持久顺序

1. 取得任务 OS 锁，核实原账号、不可变计划及源身份，再领取新的 run/generation。
2. 每次可能写入或完成发布的 POST/PATCH/HEAD/DELETE 前，先持久化 `RemoteWrite` 不确定性。
   保存失败不发送请求；HTTP 请求不会因数据库 revision 竞态而重放。
3. POST 201 仅代表创建接受，随后 HEAD 核实长度和确认偏移；未知偏移保持 null。
4. 默认按 2 MiB 顺序读取并 PATCH，只接受准确的 204 和预期偏移。已发送字节只用于即时进度，
   确认偏移在收到 ACK 后独立于迟到取消保存。
5. 最后一个 PATCH 后撤销旧能力，用原身份的 resume 能力重新 HEAD 核实发布。空文件也需要
   0/0 确认，不能由发送进度推断完成。

恢复显式开启，并先取得原任务锁；使用原 transfer ID/目标/长度及新的认证会话，通过 HEAD
恢复权威偏移。旧资源引用不能直接激活新会话。HEAD 404/410 不能证明未知创建或发布从未发生，
因此不能盲目 POST 重建。降低已确认偏移只能在 Reconciling 中根据实际 HEAD 证据完成。

单次请求使用无进展超时，默认 30 秒，不限制整个大文件只能传输 30 秒。源读取或已有 Go
上传统计可以刷新进展观察，但不能变成服务端确认。进度事件最多每 200 ms 发布一次，隔离
订阅者异常，不携带源路径、凭据或回环 URL。

## 冲突与停止

| 决策 | 执行含义 |
| --- | --- |
| Fail | 不覆盖，冲突交回协调层 |
| KeepBoth | 使用前置规划已经冻结的新目标；竞态冲突不再次悄悄换名 |
| Replace | 唯一允许设置覆盖的策略，仍受服务端 Modify 权限复核 |
| Skip | 先查询准确目标，存在则跳过；只有明确 404 才代表不存在 |

暂停先保存 Pause 意图，再停止并排空本地请求。调用方取消和 Dispose 只停止本地传输，
不会隐式删除服务器部分文件。取消先保存单向 Cancel 意图，排空后在新运行身份下 HEAD
核实：已经发布则保存 Completed，绝不 DELETE；确认未完成才可显式 DELETE。删除权限不足
与已删除分开显示，未知结果保留可核实状态。

已完成、已取消和已跳过的任务不会被重新执行。ACK 后持久化失败保留原受保护记录并报告
本地存储故障，不能重传数据或伪装持久完成。注销/换账号由应用协调层先停止排空，
不能仅依赖执行器的 Dispose 或数据库领取规则宣称完整账号旅程已经验收。

## 显式上传队列

`IUploadCoordinator` 接收已经确认并持久化的上传任务引用，不接收临时 URL 或直接操作源文件。
每次激活绑定完整 AccountKey、已验证会话 ID 和新的激活 ID；旧激活不能操作后续账号或会话。
构造和激活不扫描历史、不自动恢复，也不因网络错误不断重试原写入。

队列默认最多三个本机执行，可配置为一至三个。取消核实同样占用执行名额；相同规范化目标
不能并行执行，不相关目标仍可前进。持久层的全局领取上限和执行器的原生锁仍是跨实例保护，
本机排队不能代替它们。Busy、冲突及未知结果保留原任务证据，由显式操作重新核实。

Pause/Cancel 先保存意图，再移除待执行项或停止本机运行。停止排空先关闭入口，等待本机
执行释放资源；存储失败也不能放任其他本机上传继续执行。停止/切换本身不发远端删除。
队列事件只提供安全状态和区分已发送字节、已确认偏移的进度，保持原激活和执行身份，
不携带本地路径、远端 wire path 或租约地址。

应用接入在 Connect/Restore/Logout 等编排边界先停止排空，再退休会话；
不能在服务的 `RetireAsync` 内等待本队列，否则执行器
等待租约获取失败后的会话退休时可能形成循环等待。

当前执行器将正常关闭产生的调用方取消保存为 Pause，尚不能区分用户主动暂停与生命周期
挂起。因此本模块只提供显式恢复，不能宣称 `AutomaticResume` 或重启自动续传已完成。

## 单文件原生入口与应用协调

`IUploadService` 是浏览器使用的上传入口，`UploadApplicationService` 在已有连接与
连接目录接口外编排队列。原生文件选择和目标确认后，提交固定请求 ID、原始父目录引用
及本地文件路径；基础设施保留父目录 opaque wirePath，仅编码新叶名，先持久创建任务
再入队。相同请求 ID 不创建第二个任务，不在 UI 中构造服务器地址或租约。

首切片每次选择一个文件，固定 Fail 冲突策略，不覆盖同名目标。独立上传提示和详情对话框
显示真实阶段与服务端确认偏移，已发送字节不等于确认；关闭详情只关闭展示。取消要求显式
确认；远端删除未确认时不能显示已清理。历史分页只读取当前账号记录，不自动执行。
手动恢复或核实始终使用原任务；已持久取消意图不会因“恢复”变为继续上传。

连接或恢复成功时才安装新的上传 authority；旧 picker、确认窗口、进度和失效事件不能
操作替换后的会话。连接切换、注销、遗忘及应用关闭先关闭上传入口、等待本地句柄释放，
随后退休底层会话。底层失效通知只立即撤销 authority 并安排独立排空，不在上传执行栈
中反向等待队列。遗忘仍保留持久任务与业务 journal 的既有保护。

完成提示以持久 Completed、RemotePublished 和无未知结果为准；目录自动刷新还必须
匹配提交或手动恢复时捕获的原会话与当前目录。文件夹/批量上传、覆盖选择、完整任务页面
和自动恢复不在此切片范围。原生视觉、选择器与实际账号切换交互仍须独立验收。

## 验证范围

执行器测试覆盖协议、存储先于发送、意图竞态、超时和未知结果；原生文件测试覆盖共享访问、
身份、重解析点、长路径和执行锁。真实旅程使用隔离的自有合成文件、服务端和 Go Host。
它们不替代原生上传页面、目录批次、真实安装、网络切换及最终同 SHA 验收。
