# 栖卷 Windows 0.8.165

0.8.164 收口了压缩包预览；本版回到 P1 的收藏与标签页。代码审计发现两处可复现的层级/空状态问题，
并用真实分组、重命名与标签操作验证了分组菜单和标签模式。

## 现状取证

- `ResourceCollectionsControl.Render` 的分组过滤固定包含 `分组不可用`，即使当前账号没有任何
  指向已删除分组的收藏；用户会在正常状态下看到一个诊断项。
- 标签模式且账号没有标签时，顶部显示“暂无标签”，下方 `TagResourcesArea` 仍占用半屏并显示
  “选择标签 / 选择标签以查看关联资源”，同一个空状态出现两次，互相矛盾。
- 分组菜单、重命名、标签创建此前没有真实操作实拍；0.8.161 之后的行选中态也需要复核。

## 改了什么

1. `分组不可用` 只在确实存在缺失分组收藏时加入过滤列表；健康账号只显示“全部收藏 / 未分组 / 分组名”。
2. 标签模式无标签时隐藏下方 `TagResourcesArea`，`TagResourcesRow` 归零，只保留顶部“暂无标签”空状态；
   有标签但未选中时仍显示下方“选择标签”提示。
3. 不改动分组/标签的写入、冲突策略与结果未知保护；本版只收口过滤与空状态。
4. 版本号 `0.8.165` / `FileVersion 0.8.165.0`。

## 验证

- Release x64 构建 **0 警告 0 错误**，两次独立数据根启动冒烟均 `GATE=PASS`。
- `20261105-collections08165/Probe-Collections.ps1`：真实服务端 + 真实夹具，浅色 `light4`、
  深色 `dark1` **各 28 项 PASS、0 FAIL**：
  - 从文件列表选中 `回归-样张.png`，打开“管理收藏与标签”，页面标题与“此分组暂无收藏”空状态正确。
  - 展开分组过滤后 **不存在** “分组不可用”项（修复验证）。
  - “更多收藏操作 → 新建分组”创建 `测试分组`；选中分组后“更多分组操作”启用，
    菜单出现“编辑当前分组 / 删除当前分组”；“编辑当前分组”改名为 `测试分组改名` 后新名称出现。
  - 切换到标签模式：显示“暂无标签”，**不再出现**重复的“选择标签”空状态；
    “新建标签”创建 `测试标签`，选中后“编辑/移除”命令启用，关联资源区显示“此标签暂无关联资源”。
  - 实拍：`light4/collections-favorites-empty.png`、`collections-group-menu.png`、
    `collections-tag-mode.png`；`dark1/` 同名一套。
- **判读说明**：
  - 标签行选中态的粗黑外框是 UIA 程序化聚焦产生的焦点环；鼠标点击不会出现，属于测试伪影。
  - 分组菜单实拍使用全屏抓取，因为 MenuFlyout 是独立弹层，主窗截图会把它裁掉；
    全屏图会带上桌面与其他窗口，菜单两项 UIA 已逐项断言存在。
  - 分组过滤/标签行的焦点框与深色对比度以真机鼠标操作为准；本版不改选择器全局焦点模板。
- 连接页 `Invoke` 偶发抖动重试后通过，属探针已知抖动，不计产品缺陷。
