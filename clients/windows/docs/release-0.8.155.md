# 栖卷 Windows 0.8.155

用户实机截图指出「最基本的排版布局对齐都没做好」。这条批评成立：本地服务端页的「标签 | 值 | 操作」网格
有四处系统性对齐缺陷，0.8.152 交付时我只核了按钮右边缘，没有核标签与值的基线关系。本版全部修掉并留下
可复核的数字断言。

## 修了什么

1. **值文本没有垂直基准**（最刺眼的一条）。标签写了 `VerticalAlignment="Center"`，值没写 → 值默认顶对齐。
   只要同一行里有 36 DIP 的按钮把行高撑起来，标签与值就错开半行。实测错位量：
   日志目录行 12px、用户名/密码行 **14px**（150% 缩放下约 9 DIP）。现在标签与值中心差 ≤0.5px。
2. **同类路径行的右边缘不一致**。「数据目录」的值写了 `Grid.ColumnSpan="2"` 跨过操作列，「日志目录」没有，
   于是两行同样长度的路径在不同位置被省略号截断。去掉跨列后五行值右边缘统一（实测同为 1185）。
3. **一行一个按钮与一行两个按钮右边缘不齐**。「用户名」行 1 个复制按钮、「密码」行 2 个按钮，
   操作列是 `Auto` → 两行值的右边缘和按钮右边缘都不同。操作列改为固定 76 DIP（36+4+36）并让按钮右对齐。
4. **两张堆叠卡的值左边缘不齐**。「本机构建」标签列 84、「启动与账号」标签列 64，窄窗口下两卡上下堆叠时
   值的起始位置不一样。统一为 84。
5. **部署卡里 `Margin="0,22,0,0"` 这个凑出来的数字**。密码行原本是「标签+输入框」一个 StackPanel、
   按钮另一个 StackPanel 底部对齐再加 22px 边距 —— 22 是「标签高+间距」的手算值，差 1px 就歪。
   改成两行 Grid（第二行固定 36 DIP），按钮与输入框天然同轴；「文件夹路径」行同样重写，去掉
   `VerticalAlignment="Bottom"` 依赖。
6. **空闲的 ProgressRing 在头部占位**。只把 `IsActive` 设 false 时它仍占 20 DIP，并在标题右侧留下淡色残影
   （用户截图里那个蓝色小弧）。改为 `Visibility="Collapsed"`，头部按钮与标题的间隙从 54px 降到 12px
   （= 8 DIP 的 StackPanel 间距）。

  五行事实行标签/值中心差 0–0.5px；值右边缘唯一（1185）；用户名/密码行标签值同轴（1142 vs 1142）；
  两行复制按钮右边缘同为 1254 = 卡片内容右边缘；密码行按钮与输入框同轴（639 vs 639）；
  头部环状占位间隙 12px ≤ 21px 上限。
- **实拍 12 张**（浅/深色各 6 张：`shots-light/`、`shots-dark/`）：检测卡 + 部署表单、高级限定共享范围展开、
  已部署宽窗、凭据显示、仅错误日志、1180 窄窗。深色下文字对比与描边正常。
  这是本地服务端页**第一次**拿到真实截图（0.8.152–0.8.154 三轮都因会话锁定只有数值证据）。
- Release x64 构建 0 警告 0 错误；两次启动冒烟 `GATE=PASS`。

## 顺带记录

  本轮在干净机器上另跑了一次全链路 29 项（见下一节）作为对齐改动后的回归确认。

  拒绝再部署第二个，并把它当作用户已有的服务端提供「连接 / 打开 Web 端」——这是设计意图，不是缺陷。
  它的来源与处理见下一节。

## 顺带处理：机器上残留的旧服务端托管

用户机器上 8888 端口反复出现一个不是本客户端启动的 `filebrowser.exe`。查清了来源：那是更早的独立项目
`C:\Apps\WinFileBrowser` 自己装的托管三件套，与栖卷客户端无关：

| 机制 | 实体 | 证据 |
|---|---|---|
| 开机自启 | 计划任务 `win-file-browser-system`（ONSTART，SYSTEM）、`win-file-browser-onlogon`（登录触发） | 11/01 15:47 开机 → 15:48 `service-start.log` 写入 “starting filebrowser” |
| 异常自动重启 | 计划任务 `win-file-browser-watchdog`（每 5 分钟）跑 `watchdog-win-file-browser.cmd`：8888 没在听就杀 `filebrowser`、复制新 exe、重新拉起 | `watchdog.log` 22:03:01 tick → 22:03:03 `deploy/restart begin` → 22:03:05 `copied 88248832`；23:13/23:18/23:23 healthy |
| 对局域网开放 | 入站防火墙规则 `WinFileBrowser TCP 8888`，且服务参数是 `--address 0.0.0.0` | 规则存在 |
| WinSW 服务 | `win-file-browser-service.xml` 配了 `<onfailure action="restart" delay="10 sec"/>`，但从未安装（安装脚本里该行被注释） | `Get-Service win-file-browser` 不存在 |

这解释了用户 21:5x 手动 `Stop-Process` 之后 22:03 它又复活。**处理结果**（提权脚本
`20261102-server08155/Disable-OldFileBrowserHost.ps1`，用户执行）：三个计划任务全部 `disable`（**保留 XML 与文件，
数据库/日志/exe 一个没删，可随时恢复**）、8888 入站规则删除（共 4 条变体）、当前进程结束。
复核：23:45 时 `watchdog.log` 最后一条仍是 23:33，即 23:38 与 23:43 两个周期都没有再跑；
`filebrowser` 进程数 0、8888 未监听。客户端自己的持久化确认为干净：HKCU Run 无 `FilewayLocalServer`，
用户那份 0.8.152 部署的 `autoStart`/`autoRestart` 都是 false —— 全机只剩客户端里那两个开关。

## 全链路复测（机器干净后）

`20261102-server08155/full2/report.txt` **29 项全通过**：无服务端时不显示检测卡、端口预填 8888、
部署按钮可用 → 部署并在 8888 起来 → 检测卡回显自己的实例、共享范围「整台电脑（所有盘符）」、
`/health` 返回 `{"status":"OK"}` → 日志静置 6 秒行不重建 → 浏览器打开出现「登录 - File Browser」
（这条在 0.8.154 因浏览器窗口标题探测方式不对而缺证，本轮补齐）→ 免密连接进入工作区并列出 C/D 盘 →
停止（`停止事件在 0ms 内投递，进程在 254ms 内退出`）→ 检测卡随端口关闭而消失 → 从「已停止」再次启动成功 →
二次停止正常。
