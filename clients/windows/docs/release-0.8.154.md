# 栖卷 Windows 0.8.154

两条来自用户的新要求：**整个系统只允许运行一个服务端**，以及**默认端口回到 8888（可自定义）**。
实现过程中用一个真实升级场景撞出一个更严重的缺陷，一并修掉。

## 一、全系统只允许一个服务端

- 服务层新增 `EnsureSingleServerAsync`：在做任何事之前重新扫描本机（不吃 15 秒缓存），只要有**任何一个**
  Fileway 服务端在应答、且它不是“这次要拉起的那个进程”，就抛冲突，消息点名端口 / 进程名 / PID，
  并给两条出路：先停它，或直接用现有的那个（「连接」）。
- 两个入口都挂：`DeployAndStartAsync`（在建库**之前**，替代 0.8.153 那个只查单个端口的窄检查）、
  `StartCoreAsync`（在自己的进程没起来也没被收养之后、真正 `CreateProcessW` 之前）。
  看门狗的自动重启走同一条路，所以外来实例存在时不会偷偷拉起第二个。
- 页面不再让用户点了才报错：检测到外来服务端时「部署并启动」直接置灰，部署卡说明改为
  “本机已经有一个服务端在运行…系统只允许运行一个”；已部署但停止、且外来实例在跑时，主按钮置灰、
  文案变「已有其他服务端」、读屏名“本机已有其他服务端在运行，无法启动第二个”。
  检测卡的「连接 / 打开 Web 端」始终可用。
- 安全边界不变：**客户端绝不向不是自己启动的进程发信号**。“停掉那个外来的”只能由用户自己做。

## 二、端口默认回到固定 8888

撤销 0.8.153 的“自动避开占用端口”（`NextFreePort` / `SuggestPort` / 端口输入框的改动跟踪）。
新规则下换端口并不能让第二个服务端合法存在，预填 8889 只会误导用户以为可以部署。
端口仍然可以在表单里手动改。

## 三、顺带修掉：升级会把已有部署变成“组件缺失”

验证时用 0.8.153 的部署数据根跑 0.8.154 客户端，页面直接显示「服务端组件缺失」——
因为 `local-server.json` 记的是**部署时**那份 `fileway-server.exe` 的 sha256，客户端一升级，
安装包里的 exe 哈希就变了，旧实现把“文档哈希 ≠ 回执哈希”判成组件被篡改。
**这条会立刻砸在真实用户身上**：你安装版 0.8.152 里那份 18099 部署，装完 0.8.153 就会永久起不来。

修法（保持防篡改语义）：
- 完整性只以“磁盘上的随包 exe 是否匹配随包回执”为准（`VerifyExecutable`），这是真正的篡改判据；
  文档里记的哈希与回执不一致时视为“应用升级换了服务端”，**自愈写回新哈希**而不是报错。
- 进程归属判定（`Matches` / `TryAdopt` / `RecordExit`）从“只认部署时那条路径”改为
  “部署时记录的路径或当前安装目录的路径都算自己的”，否则升级后正在运行的旧进程会被误判为
  “端口被其他进程占用”。
- 实际启动后把 `ExecutablePath` 收敛为真正拉起的那条路径。
- 数据库、端口、管理员账号、DPAPI 凭据全部不动。

## 验证（Release x64，0 警告 0 错误）

- **单服务端限制** `20261102-server08154/single2/report.txt`：在 8888 上确有外来 `filebrowser.exe` 的真实机器上，
  回显该实例 ✓、端口预填回到 8888 ✓、部署按钮 `IsEnabled=False` ✓、说明文案出现单服务端规则 ✓、
  「连接」仍可用且地址预填正确 ✓、不会替外来实例免密登录 ✓、已部署场景下启动同样被拒 ✓、
  全程没有拉起第二个服务端（8889 未监听）✓、外来服务端未被影响 ✓。
- **升级路径** `upgrade1/report.txt`：用 0.8.153 的部署数据根跑 0.8.154 → 状态是「已停止」而不是「组件缺失」✓、
  文档哈希自愈为新的随包 exe 哈希（`1e4a112f…` → `e0e2f928…`，与 `Get-FileHash` 实测一致）✓、
  端口/管理员账号/凭据文件均未变 ✓。
- 两次启动冒烟 15 秒 / 20 秒均 `GATE=PASS`（`data/smoke-a`、`data/smoke-b`）。

## 未验证 / 已知边界

- **正向全链路（机器上没有其他服务端时：部署 → 启动 → 免密连接 → 停止）本版无法回归**，
  因为 8888 上那个提权的 `filebrowser.exe` 一直在跑，而它不是本客户端启动的、客户端不会去停它，
  我这个非管理员令牌也停不掉（`Stop-Process` 返回“拒绝访问”，父进程已退出、不是服务也不是计划任务）。
  需要用户用管理员终端执行一次 `Stop-Process -Name filebrowser -Force`，之后重跑 0.8.153 那套 24 项功能回归。
- 主按钮的**可见**文案「已有其他服务端」未被 UIA 独立证实：`AutomationProperties.Name` 覆盖后按钮内
  TextBlock 不再出现在内容视图里，可见文案与读屏名由同一处赋值，需实拍确认（会话锁定，待补）。
- 实拍截图与数值几何复核仍缺（0.8.153 起同一原因：会话锁定）。
- 单服务端规则是“启动前检查”，不是持有全局锁：若两个客户端实例几乎同时点部署，理论上仍有竞态窗口。
- 挂载范围仍只有“整台电脑 / 单个文件夹”两档，按盘符勾选需要服务端支持多 root，另开版本。
- 安装包为本机未签名候选。
