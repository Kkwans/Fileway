# Android 页面与窗口约定

## 页面覆盖

页面检查沿 `ClientApp` 的实际分流进行。主导航壳没有覆盖独立预览器和二级页面，修改主导航不能视为已经适配所有页面。

| 页面组 | 实现入口 | 安全区责任 |
| --- | --- | --- |
| 文件、最近、资料、任务、设置 | `FilewayAppShell` 和各页面 Scaffold | 页面消费 Scaffold 内容边距；主导航负责手势区 |
| 压缩包浏览 | `ArchiveScreen` | 标题栏负责顶部，底部动作区负责导航区及键盘，列表消费内容边距 |
| 文档预览与编辑、命令输出 | `DocumentPreviewScreen`、`DocumentEditorScreen`、`ShellScreen` | Scaffold 内容边距；编辑界面另处理 IME |
| 图片与本机缓存图库 | `ImageScreen`、`CacheGalleryScreen` | 图片背景覆盖全窗；控件处于安全区 |
| 音频、视频播放器 | `AudioScreen`、`PlayerScreen` | 各自深色窗口状态与安全区，保留原生播放 Surface |
| 账户、用户管理、服务器设置、更新 | 对应独立 Screen | 自有 Scaffold 和动作区，不能依赖主导航 |
| 详情、编辑、目标目录、许可证 | `FileOperationSheet` / `FileOperationDialog` | 独立原生窗口，按下述窗口规则处理 |
| 确认、日期、锚点菜单、播放反馈 | `FilewayAlertDialog`、`FilewayDatePickerDialog`、`FilewayMenu`、播放器窗口 | 每个窗口自行处理边界、主题、定位与触摸语义 |

## 安全区与材质

- 背景延伸到状态栏及手势导航区；内容、按钮避开系统栏、切口与键盘。每个方向的边距只由一个层级消费。
- `FilewayTopAppBar` 保护横向切口；调用方负责顶部状态栏。自定义标题栏不会自动获得 Material TopAppBar 的状态栏边距。
- 贴底面板覆盖导航背景，在动作下方保留一次导航安全距离。居中对话框和锚点菜单留在安全窗口内，不能为了沉浸变成全屏模糊窗口。
- Dialog 与 Activity 是不同 Window。原生窗口的布局、安全区、系统栏明暗、透明背景与对比度遮罩需要独立设置，不能仅改变 Compose 颜色。
- 浮层使用共享玻璃组件与主题色，内容先给出稳定框架，异步数据回填；不捕捉视频帧循环模拟模糊。
- 触摸态在圆角表面内裁切。标题、图标、正文和动作使用共享样式，同组图标保持同源；紧凑外观仍保留足够触区。

## 列表与动作

- 文件及记录列表：单击详情，长按多选，可打开对象双击打开。压缩包里的目录与文件遵循同一规则。
- 多选入口在原标题栏原位切换为退出；其他顶部动作保留。选择条提供计数、全选、反选和批量动作，清空选择不退出模式。
- 目标目录选择属于选择器，使用共享 `FilewayDirectoryRow` 单击进入；不套用普通文件详情流程。
- 一个正文拥有一个主要滚动容器。不得用横屏固定列表高度、叠套滚动或常驻大表单挤压核心内容。
- 包内条目使用 `ArchiveEntry` 的相对原始路径；不得伪装成 NAS `ResourceRef`。导航显示名称与 opaque wire path 分开处理。
- 压缩包解压保留被阻止条目、截断禁用、同名跳过、选择数量限制、权限、取消及未知提交结果的恢复入口。取消一个继承选中的子项不能取消其他目录的选择。
- 提交配置在确认面板完成，浏览页面保持紧凑的任务入口；成功后的结果、跳过原因与目标目录仍可访问。
- 有标题栏关闭或返回入口的面板不再放置无作用的底部关闭按钮。单个实际动作占满一行，多个动作按同一轴线等宽排布。

## 验证边界

源码检查、构建、定向测试和实际设备观感是不同证据。系统栏、键盘、圆角、首次弹出定位及多选入口需要在目标设备中验证；复用未受影响的有效结果，按完整模块集中收集与修复问题。
