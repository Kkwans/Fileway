# Windows 传输通道

Windows 通过共享 Go 核心访问服务器。文件字节走短期回环租约，控制命令走私有 IPC；
UI 不构造服务器 URL、不读取 token，也不持有租约地址。上传通道是持久传输任务的基础，
不等于已完成上传页面、队列或应用启动恢复。单文件执行见
[上传执行器](upload-execution.md)，完整产品范围继续见
[产品路线](product-roadmap.md)的 0.3。

## 上传能力与归属

`IUploadLeaseProvider` 接收不可变目标、已知长度、稳定 transfer ID，以及明确的覆盖与
恢复选择。当前使用已有 TUS 实现，不重新实现服务端上传协议或在 JSON 中搬运文件字节。
本地能力创建需要 Create；覆盖还需要 Modify，不能错误地要求 Download 或 Delete。
真正的 TUS 请求继续由服务端复核当前用户、scope、目标与权限。

目标使用原始 wire 路径，不能从显示名称重建。可选批次信息只映射已有的五个
`X-Upload-*` 追踪字段；名称编码一次，字段有长度和格式边界，不接受任意调用方认证头。
本地租约绑定原会话，不能切换账号后重用。持久任务保存账号、目标、transfer ID、长度与
本地源身份，不保存租约地址、token 或响应中的临时访问能力。

租约沿用现有会话退出和撤销机制。取消本地访问、销毁租约或关闭 Go 会话只是暂停数据通道，
不会删除远端部分文件。远端取消需要明确的 TUS DELETE 和 Delete 权限；已经发布的完整
目标必须受保护。取消或刷新失败后得到的迟到租约要清理，不能交给替换后的会话。

## 确认与恢复

| 观察 | 含义与后续动作 |
| --- | --- |
| 创建能力成功 | 只得到本地通道，尚未发送文件或建立远端上传 |
| POST 201 | 服务端接受创建；统计确认偏移仍未知，随后用 HEAD 核实 |
| HEAD 200 | 核实相同目标、transfer ID、总长度及确认偏移；HEAD 也可能完成中断后的发布 |
| PATCH 204 | 只接受与请求偏移和实际发送长度准确匹配的确认偏移 |
| 最后一个 PATCH 成功 | 当前 Go 租约结束；核实发布时撤销它，再建立相同身份的 resume 租约并 HEAD |
| 零字节 POST 201 | 服务端可能已发布完整空文件；仍需 HEAD 确认 0/0，不发送空 PATCH |
| 断流、丢失确认或异常 ACK | 不重发原写入；保留未知状态，通过新的 resume 租约与 HEAD 核实 |
| DELETE 204 | 已取消原私有上传；不能据此推断曾经发布的其他文件被删除 |

同一账号可在新的 Go 会话中按原身份重建恢复通道；原资源引用本身仍属于旧会话，不能
直接拿来激活新会话。恢复必须重新核实本地源、账号和目标，不能把新文件追加到旧 part。

## 统计边界

`UploadLeaseStatistics` 分别提供累计读取字节、服务端确认偏移、当前请求字节、请求编号、
计时与活动状态。初始 `acceptedOffset=-1` 映射为未知，不能伪造为已确认的零字节。
累计发送字节可能包含多次请求，不能拿它当确认偏移或服务端落盘速度；空闲状态、
发送到总长度和界面百分比都不能证明上传已经完成。统计读取有原会话和释放竞态检查。

## 下载源：传输 fresh-only，播放读取可选条件版本

`IDownloadSourceProvider` 现已接通经过认证、Download 权限复核的单文件元数据、
未缓存的只读回环租约和 SHA-256。目标始终使用原始 opaque wirePath，显示名称和路径
不能替代身份。获取租约前再次核对文件身份及长度；创建能力不会开始读取文件字节、
写入本地目标，或创建传输任务及业务操作 journal。下载租约只发送 wirePath，
不接入媒体缓存、缓存归属登记或缓存预算。

传输入口仍明确返回 `SourceVersion=null`、`SupportsResume=false`，只允许从头进行
不带版本条件的新读取；`IDownloadSourceProvider` 的三个入口拒绝调用方提供的非 null
SourceVersion，元数据及校验响应显露版本时也拒绝。文件夹与动态归档不由此单文件入口处理。

shared/core 与 server 已提供 additive `conditionalDownloadV1`：能力清单、资源元数据、
raw 读取响应头和版本条件均保持同一 opaque sourceVersion。Windows 通过独立的
`IConditionalDownloadSourceProvider` 只给边下边播的 Range 读取使用这项能力：每次读取
重新观察版本，临时 lease 和 `X-Fileway-Source-Version` 必须匹配；不支持该能力的服务器
继续回落到上面的 fresh-only 播放读取。该接口不写传输 checkpoint、不开放旧 partial
追加，也不代表下载续传或历史文件恢复。

SHA-256 沿用既有长读取预算与权限、取消、会话复核，读取期间不占用会话操作 gate。
摘要返回前核对请求长度、原始 modified 文本及计算前后元数据，并检查每次响应的
版本字段。它验证当前新读取的源观察，不证明不可变历史内容，也不能授权追加旧的
部分文件。后续下载执行器仍须验证 HTTP 状态、Range/Content-Range、版本及实际字节数。

租约始终绑定原会话。并发释放共享一次 revoke 的完成结果；下载释放只有在撤销得到
确认，或原会话已确认关闭后才完成。撤销失败或结果未知时退役原会话，关闭失败则
沿用 Host shutdown 回退；无法确认清理时返回错误。已派发的能力创建遇到取消、超时、
过大或无效响应时可能隐藏迟到能力，也会关闭原会话，不重放创建请求，不影响替换后的会话。
账号注销与租约释放共享内层完成结果，内层释放不等待账号退役，避免相互等待。

## 后续任务层

同一 SQLite 中的任务计划、源与工作文件证据、确认 checkpoint、generation、取消意图、
并发领取和结果未知记录已由 [持久传输任务](transfer-state.md)实现。
单文件执行器接通了原生源文件、OS 执行锁、TUS 分块和持久检查点；
显式上传队列及单文件原生入口已接入应用账号切换停止排空；目录批次、完整任务页面
及原生逐项旅程仍待完成。
恢复不能自动重放业务写入。
[单文件 fresh 下载执行器](download-execution.md)已接通同目录 owned partial、flush 后确认、
本地/服务器 SHA-256、无覆盖发布与发布中断的本地核实；原生入口与上传共用账号生命周期边界。
它不支持断点续传。完整下载续传、目录批次和任务页面仍独立推进；播放侧的条件版本
Range 验证已接入，但不改变传输执行器的 fresh-only 语义。
媒体缓存、默认下载目录设置和服务端复制任务均不能替代传输执行和真实原生旅程验证。
