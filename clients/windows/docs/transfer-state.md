# 持久传输任务

`ITransferTaskStore` 在现有本地数据库中保存文件执行单元。上传通道见
[传输通道](transfer-transport.md)。任务记录、调度器、字节传输和原生界面分别承担职责；
打开数据库只恢复证据，不自动启动请求或重放写入。

## 身份、意图与事实

任务 UUID 在同一数据库全局唯一；所有读取和更新仍要求完整 AccountKey。
不可变计划固定方向、远端原始路径、本地源或最终目标、冲突策略和自动恢复选择。
批次与序号用于后续文件夹聚合，不伪造当前尚未枚举的项目数。

用户的 Run/Pause/Cancel 意图独立于实际执行阶段。取消不会清除已确认偏移，也不会把
真实成功覆盖成失败。Cancel 不能改回 Run；需要重新执行时创建新任务。
Completed、Canceled、Skipped 不能被迟到回调重新启动或降级。

每次执行领取新的 run ID 与 generation。检查点还以 revision 比较交换；旧执行者即使
读取到最新 revision，也不能绕过运行身份更新新执行者的数据。修改用户意图只增加
revision，允许原运行者重新读取后保存真实迟到确认，不能重发原 I/O。

任务领取在事务或内存锁中限制最多三个活动运行，并对活动或结果未知的同目标保留占用。
下载按本地路径、上传按账号与原始目标字节区分。数据库中的路径比较只解决词法冲突，
执行器仍须核实重解析点、硬链接、原生文件身份、同卷要求和独占文件访问。

## 检查点与发布

| 数据 | 保证与边界 |
| --- | --- |
| 源快照 | 固定长度、时间和可用的版本/原生身份；改变源需新任务，不是历史内容快照 |
| 确认偏移 | 上传为服务端 ACK，下载为已 flush 的本地前缀；未知用 null，不能用已发送字节替代 |
| 工作文件 | 记录同目录临时文件、备份及发布后身份；路径记录不等于真实所有权或删除授权 |
| 摘要 | 下载完成要求本地与服务端 SHA-256 一致；不能用文件长度代替完整性验证 |
| 不确定性 | 分别保留远端写入和本地发布的不确定状态，核实前不显示完成或盲目重放 |

只有 Reconciling 阶段可根据外部证据降低到共同安全前缀。缺失部分文件的重建受源身份、
零偏移与未发生发布等条件约束；存储层本身不会扫描、截断或删除文件。
发布开始后不能直接宣称已暂停或已取消，必须先核实完整目标、备份和临时文件的实际状态。

上传完成需要确认完整长度及远端发布。下载完成还需要一致摘要与发布文件身份。
本地取消与服务端确认删除分开记录；未获得远端取消确认时，不能声称服务器部分文件已删除。
已取消或已跳过的终态不能保留未核实结果；未知结果继续进入可核实状态，避免永久无法恢复。

## 注销、遗忘与恢复

任务保存不可变的连接来源摘要，覆盖地址和网络/代理策略。遗忘后保留的历史仍约束同一
source revision，不能重新添加同一身份却把旧任务带到另一服务器；摘要不包含凭据。

Create/Claim 要求原账号档案仍存在且没有待注销意图。活跃运行或未核实结果阻止遗忘和
连接身份替换；事务内检查避免另一实例绕过。服务层在注销或删除凭据之前先检查，
不会为了拒绝遗忘而先让用户退出登录。

注销仍被允许；原运行者可以保存迟到事实，这不会恢复令牌或会话。安全排队/暂停的记录
可以留在已遗忘账号名下，不能绑定到新账号。执行器还需完成停止与排空，再允许新账号工作。

恢复领取只建立新的数据写入身份；调用者必须先确认旧执行已停止，并取得真实独占访问。
它不证明进程已经死亡，也不授权自动重放写操作。[单文件上传执行器](upload-execution.md)
在领取前取得真实 OS 锁，再用 HEAD 核实原上传。显式上传队列核心已提供有界调度、
暂停/取消及停止排空；目录批次、条件下载、应用账号切换接入与启动恢复旅程仍须按产品
路线接入与验证，不能以数据库重开或队列测试通过代替这些能力。
