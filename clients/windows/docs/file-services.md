# Windows 文件服务契约

`FilewayClientServices` 实现 Core 的类型化接口；UI 不构造服务端 URL、不读取凭据，
不直接修改操作记录。所有资源都携带完整 AccountKey；远端 wire 路径、显示路径和本地路径
保持分离。服务能力已实现不表示对应原生页面或完整用户旅程已经验收。

## 搜索和校验

`IServerSearchService` 提供当前目录和递归搜索。查询沿用服务端语法，返回增量结果、
已接收数量及唯一结束原因，区分完成、数量限制、服务端超时、取消、错误和会话更换。
消费结束或取消时有界释放原会话的搜索 handle，不能将迟到结果绑定到新连接。

服务端 `searchWirePathV1` 返回 `wirePath` 与 `pathVerified`，共享 Go 核心和 Windows
分别核实路径处于搜索起点和指定层级。旧端只有可证明的严格 UTF-8 相对路径才允许构建
资源身份；有损显示名称或矛盾的服务端 wire 结果只展示，不能据此打开或写入文件。
Windows 服务端会过滤无法安全映射到 Windows 文件名的非 UTF-8 文件；Linux 的原始
字节身份保持不变。新增字段不改变旧 NDJSON/display 字段的含义。

`IFileChecksumService` 支持 MD5、SHA-1、SHA-256、SHA-512，以及可选预期摘要比较。
校验必须有下载权限且目标为文件。计算前后核对资源身份、类型、大小和修改时间，
源变化不报告有效结果。Go 计算预算为 15 分钟，Host 请求允许 16 分钟收尾；长读不占用
会话操作锁等待计算，其他文件/任务请求和注销可以前进。没有源版本条件时，元数据一致
仍不能被描述为对抗任意同大小同时间改写的强快照保证。

## 最近访问

`IRecentAccessService` 使用已有 `/api/recent` 列表与记录接口，不与播放位置、播放历史
或本地缓存混用。列表按服务端顺序和时间返回，最多 100 项；接口没有分页、清空或删除
能力，客户端不能伪造这些功能。历史项仍可能指向已删除、换内容或不再有权访问的路径，
真正打开时必须重新读取当前元数据与权限，不能将历史记录描述为原文件的不可变快照。

可信 `wirePath` 保留原始字节身份；旧响应只有可证明的严格 UTF-8 路径才建立可操作引用，
其他历史仅可展示。列表和资源引用绑定原账号与会话，迟到列表不能挂到替换后的连接。

记录只能发生在真实远端资源成功打开之后，选择、预取、失败打开和本地文件不触发记录。
它是服务端拥有的有界次级副作用，不进入文件业务操作日志、不设本地重放队列，失败不能
逆转已成功的打开或阻止遗忘连接。请求只发送一次；精确的 HTTP 200、记录 ID、服务端
时间和源身份共同确认成功，迟到的确认也不能复活会话。明确拒绝、发送前未提交和发送后
结果未知分别返回；500 可能发生在服务端已经保存记录之后，不能自动重试或猜测失败。

## 文件写入和服务端任务

- 零字节新建文件省略 body，使用排他创建；不覆盖已有文件。
- 批量元数据按输入身份返回逐项结果，不用显示名称重新匹配。
- 批量重命名先预览再执行。执行 token 绑定账号、原会话和不可变计划，并非服务端
  reservation；执行前复核源信息，服务端仍做最终校验。提交后未知不能复用 token 重发。
- 复制/移动沿用服务端异步任务，支持 Fail、KeepBoth、Replace、Skip；默认 KeepBoth，
  Replace 需要显式选择及相应权限。全部 Skip 不发送任务，源 basename 保留原始 wire 身份。
- HTTP 202 的 `TaskAccepted` 只确认提交成功。任务运行、完成、失败、取消、被中断和
  未知新状态分别保留。取消请求已接受不等于任务已经取消；重试使用已知任务 ID，
  返回新 ID 与正确的 retryOf，不重新提交原始文件请求。

`IServerTaskService` 当前只管理当前账号自己的任务，即使登录者是管理员。分页游标原样
传递，不推算页数；未来未知 type/status 可展示但不能当作完成。归档及取消同样有业务确认
和操作记录。管理员跨用户管理属于后续产品范围。

任务列表的 `Counts` 是摘要计数，`CategoryCounts` 则按 file/background 等分类各保存一组
摘要计数，包含 all、active、attention、canceled、completed、archived。分类值不是单个总数；
未知分类/计数键保留，负值、重复键或错误结构拒绝，不把分类总数与当前页项目数混淆。

删除始终显式指定回收站模式。`ITrashService` 按 owned ID 恢复，支持四种冲突策略，
保留 `skipped` 与服务端返回的显示路径。该响应没有可信 wire 身份，不能凭显示路径
伪造可操作资源。永久删除、清空与撤销窗口不在本模块中增加入口。

## 操作记录和结果未知

已接入的文件管理、任务控制、收藏及标签业务写入采用同一顺序；上述最近访问记录
不属于这类业务操作：

```text
权限/源预检 → Intent 落盘 → DispatchMarked 落盘 → 最后身份/取消检查
           → Host 请求 → 精确业务 ACK → ACK 落盘 → 更新会话元数据
```

发送前保存失败必须零发送。DispatchMarked 表示可能已经发送；应用崩溃后不能仅凭此
标记判断成功或失败。明确业务拒绝与发送后超时、断流、异常回复分别记录。
每个写入结果携带 OperationReceipt；真实 ACK 不因本地保存、续期或注销竞态消失，
ACK 保存失败则保留确认结果并报告 `AckPersisted=false` 和存储警告。

日志接入不改变既有文件/收藏接口的错误约定：发送前失败和明确拒绝仍抛安全的
`FilewayException`，同时保留已经建立的本地记录。只有可能已执行却无法确认的写入返回
OutcomeUnknown；批量删除继续汇总逐项成功、失败和未尝试，不能把明确拒绝伪装成未知。

`IOperationHistoryService` 只读核实，不重放写入。活动操作返回 Pending，避免核实抢占
正在保存的 revision。重启后的未发送 Intent 可以确认 NotSent；已经有业务 ACK 的记录
保持确认，已知任务 ID 可以读取任务状态。源消失、目标元数据相同、回收站 ID 不见或
同标题任务都不足以证明未知操作的归属，无法证明时保留 NeedsReview。

SQLite schema 5 在原存储中保存记录，没有第二套数据库。原账号有未核实写入时禁止遗忘
或改写其连接身份；注销可以继续，迟到的结果只写原记录，不能复活登录或污染另一账号。
平台内存实现明确非持久，结果不能声称跨重启恢复。完整迁移与凭据策略见
[本地连接数据](local-data.md)。
