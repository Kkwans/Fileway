# 栖卷 Windows 动效

## 设计目标

动效应连续、自然、跟随操作且可中断。参考 Apple 的运动设计理念，以空间关系、速度连续性和
反馈解释状态变化；不以统一缩短时长为目标，也不把所有切换改成同一种淡入淡出。
本文更新此前 R1 的动效起始建议，具体效果以真实 Windows 原生切片和用户验收为准。

- 操作立即被接受，视觉过渡与业务执行分离；用户不必等动画结束才能继续操作。
- 新操作从当前呈现状态接续，保留合理的速度与方向；反向操作不先跳回起点，不排队播放旧动画。
- 进入与返回保持空间关系。窗口、内容、控件表达不同层次，不能所有元素同时独立弹跳。
- 自然减速和有阻尼的弹性用于有意义的几何变化，不给文件正文、进度数字或每次刷新增加装饰运动。
- 时长根据移动距离、区域大小与操作目的调整。以下为制作起点，不是 Apple 的官方数值或已测结果。

## 场景与验收

| 场景 | 预期行为 | 起始预算与边界 |
| --- | --- | --- |
| 播放器进入/退出全屏 | 视频、窗口边界与控件协同过渡，保留画面和播放位置；反向请求从当前位置接续 | 300–450 ms 起调；需要 native HWND 实测。不能把普通 XAML 缩放当作视频缩放，也不能只用黑幕或静态截图掩盖瞬间跳变 |
| 目录进入/返回 | 内容沿一致的层级关系衔接；路径和选择及时更新，返回保留原滚动位置 | 220–320 ms 起调；连续导航取消旧过渡，迟到结果不能重新播放旧页面动画 |
| 侧栏/详情展开与收起 | 宽度、内容和焦点有一致的空间关系；拖动调整宽度直接跟随指针 | 240–360 ms 起调；手动拖动期间不另加滞后动画，不改变文件操作权限 |
| 列表与网格首次加载 | 加载态自然衔接到真实内容；必要时仅初始可见项目轻微错峰 | 总过渡控制在约 350 ms；不对滚动回收、缩略图到达、排序刷新逐项重播，不破坏虚拟化 |
| 搜索/任务/传输状态 | 可解释地切换加载、部分结果、完成和错误；进度保持连续 | 160–240 ms 起调；数据状态即时生效，不用动画伪造进度或延迟取消 |
| 菜单、弹窗与提示 | 从触发位置建立关系，材质与层级稳定；消失与进入路径相应 | 180–280 ms 起调；优先复用 WinUI 原生交互，避免双重动画和焦点闪跳 |
| 播放控件显隐 | 渐变遮罩与控件一起自然退场，鼠标真实移动或操作后恢复 | 保持已验收的 Screenbox 视觉；系统生成的同坐标鼠标消息、窗口内部激活不能重复唤醒 |

## 原生实现约束

WinUI 内容优先使用现有 XAML/Composition 动画能力，不引入另一套 UI 框架。动画拥有者负责
取消、重定向及关闭清理，视图代次变化后不能继续更新旧对象。

libmpv 当前视频输出为原生 HWND，不能由 XAML 的 Scale/Opacity 自动变成可动画的视频纹理。
全屏路线必须单独验证真实视频继续播放、窗口与 HUD 同步、最大化还原、DPI/多屏和 HDR 链路，
再决定几何过渡实现；还没有通过该门槛。不能为了动画关闭安全检查、改变媒体所有权或泄露资源租约。

跟随 Windows 的动画/辅助功能设置，并提供应用内进一步减少动态效果的选项。降低动态效果时，
去除大范围缩放、位移与弹性，保留必要的状态反馈、焦点及加载含义；设置读取失败时采用稳定退化。
不因辅助功能策略而延迟真实完成、取消或错误。

验收需要真实原生操作和录屏，覆盖反复进入/退出、动画中反向操作、关闭、键盘焦点及降低动态效果。
同时记录帧时间、输入延迟和资源变化；高帧率、构建成功或一张静态截图都不能单独证明动效质量。

## 依据与当前状态

Apple [Designing Fluid Interfaces](https://developer.apple.com/videos/play/wwdc2018/803/) 的官方讲解
支持即时响应、可重定向、空间一致性及连续运动这些设计原则；上述 Windows 场景与预算是本项目的应用。
Windows 的显示/隐藏会生成同坐标鼠标消息，见 Microsoft
[Why do I get spurious WM_MOUSEMOVE messages?](https://devblogs.microsoft.com/oldnewthing/20031001-00/?p=42343)。

统一动效尚未完成。当前优先修复已观察到的控件周期显隐，再交付全屏与文件导航的原生代表切片；
现有退出 CFG 缺陷、单击画面暂停及完整影音验收仍独立跟踪，不因新增动效关闭门槛。
