# Windows 本地连接数据

生产客户端通过 `SqliteProfileStore` 与 `DpapiCredentialVault` 保存连接。未传入存储的
`FilewayClientServices(host)` 仅使用进程内存，供隔离调用者和测试使用。
界面只接收 `SavedConnection` 和 `ConnectionSession`，不读取令牌。

## 数据根与并发

默认根为 `%LOCALAPPDATA%\Fileway\Preview`。开发及测试显式使用独立
`FILEWAY_WINDOWS_DATA_ROOT`，不能共享用户真实数据。程序目录、下载目录与此根分离。
应用持有 `.client.lock` 的独占文件句柄；同一数据根只允许一个应用进程，关闭时释放。
SQLite 工作在后台执行并串行访问，锁等待有界；连接启用 WAL、外键和 FULL 同步。

## Schema 8

`client.db` 用 SQLite `user_version` 管理版本。`saved_connections` 以 profile UUID 为主键，
保存 source revision、名称、服务器地址、网络/代理策略、认证方式、用户名、服务端 userId、
保持登录开关和最后连接时间；密码与会话令牌不写入 SQLite，另存于独立的 DPAPI 凭据库，见“凭据与恢复”。

`pending_logouts` 以 `(profileId, sourceRevision, serverUserId)` 为复合主键。
注销意图事务先关闭对应账号的保持登录标记，再收回会话和媒体租约，删除加密凭据后完成清理。
启动、恢复及读取档案前处理未完成意图。旧账号的清理不能删除同 profile 的新 revision 或新账号。

`client_storage_settings` 保存本机缓存根目录、独立的默认下载目录与总缓存数据上限，
默认 5,000,000,000 字节；不保存媒体或凭据。`cache_roots` 以完整 AccountKey 与缓存根为复合主键，
登记本客户端的缓存归属。发放磁盘缓存租约前必须成功登记；失败仅退回相同端点的在线读取。
目录变更保存为待生效配置，下次启动使用，
不会搬移或删除旧目录的数据。播放缓存的分块和配额由 Go 核心统一管理，见
[缓存与预加载](cache-storage.md)。

`browser_preferences` 以完整 AccountKey 与解码后的远端目录字节身份为复合主键，保存五种视图、
两组独立图标大小、当前目录类型筛选和排序。目录身份以大写十六进制存储，不使用显示路径、
Windows 本地路径归一化或 Unicode 改写。写入事务核实对应连接仍存在且没有待注销意图；
遗忘只删除该完整账号的偏好，不能误删同 profile 下的新 revision 或新账号。

`navigation_state` 以完整 AccountKey 保存最后一次成功加载的目录 wire path。写入核实连接仍存在且
没有待注销意图；替换账号、注销及遗忘会在事务内清除对应记录。启动向服务器重新核实目录，
已删除、已无权限或无效的路径回到根目录；网络或认证失败不能被当作目录不存在。

`operation_journal` 与 `operation_journal_items` 保存按完整 AccountKey 隔离的业务操作意图、
发送标记、确认结果和核实记录。仅存允许的业务字段、原始资源身份、显示字段和安全错误码，
不保存任意 Host 请求、端点、令牌或原始异常文本。更新以 revision 比较交换，迟到的取消
或核实不能覆盖已经确认的结果；SQLite 事务同时核实原连接仍存在且未进入注销。

`transfer_tasks` 保存按完整 AccountKey 隔离的文件传输计划、控制意图、执行领取和检查点。
任务 UUID 全局唯一，更新同时核实 revision 与 run/generation；本地源/目标、确认偏移、
摘要和临时文件身份都属于私有持久数据，不进入普通日志，不包含令牌或租约 URL。
同目标占用、活动数量和遗忘/身份替换保护在事务内协调，具体语义见
[持久传输任务](transfer-state.md)。数据记录不等于执行器或自动恢复已经完成。

首次仅在空数据库创建 schema。升级旧版 schema 1–7 前使用 SQLite Backup API 制作包含已提交 WAL
内容的一致备份，随后事务添加缺少的表和列；schema 8 增加目录恢复记录。备份名为
`client.db.schema<旧版本>-<随机标识>.backup`。
备份失败不开始迁移。未知更高版本或无版本但已有数据表的数据库拒绝写入，不自动重建。
不能复制运行中的 WAL 文件冒充备份，也不能只换旧程序做不兼容降级。

Windows 的 SQLite 主库与备份连接使用扩展长度路径；逻辑数据路径和备份名称保持原样。
这避免正常库路径加上备份后缀后跨过传统路径边界而使迁移失败；不会修改系统路径设置。

## 凭据与恢复

仅在登录时勾选保持登录才保存会话令牌和密码；不勾选会先持久关闭恢复资格，再删除已有凭据。
两类凭据使用独立的 DPAPI CurrentUser 加密命名空间，熵和文件名绑定完整 AccountKey；
密码文件位于仅当前 Windows 用户可访问的独立子目录，不进入 SQLite、日志或错误消息。
同目录临时写、落盘后原子替换，明文字节缓冲区用后清零。
恢复必须向服务器核验同一 userId、当前账号元数据和能力后才激活，不能采用 JWT 的旧权限作为界面权限。
续期更新同账号元数据；Go 核心拒绝把不同 userId 的续期 JWT 发布给 API 或媒体请求。

恢复先使用令牌；仅令牌缺失、不可解密、格式损坏，或服务器明确返回认证过期 401 时，
才用该账号的本机密码登录一次。网络、403、协议失败及身份不一致不触发密码重试。
旧版只保存过令牌的连接可继续使用有效令牌，失效后需输入密码一次。
远端密码修改已确认后独立更新本机密码；本机保存失败显示警告，不把远端成功改为失败或重复修改。

Disconnect 保留档案和已选择保存的凭据；Logout 清会话、令牌、密码和目录恢复记录但保留档案；Forget 同时移除该档案。
改变服务器或安全路由必须创建新 source revision。不能把旧凭据重新绑定到新地址。
网络、权限、认证、本地存储和凭据失败分别反馈安全错误；不重放写操作。

尚有待核实写入、活跃传输或未核实传输结果时，不能遗忘该账号或用另一 revision/用户覆盖原连接档案；可以新建独立连接。
注销仍允许进行并删除凭据，但不删除操作历史。已经发出的操作可以向原账号记录迟到的真实
确认，这不恢复登录状态或凭据。只有原账号重新通过认证后，服务才开放其操作历史和只读核实。
进程内存存储明确报告不能跨重启恢复，不得把它当作 SQLite 的持久保证。详见
[文件服务契约](file-services.md)。

已确认的远端写入不因续期或本地保存失败变成失败。安全事件携带 AccountKey 和 SessionId，
旧会话的迟到通知不能关闭新会话。会话撤销失败时终止自有核心进程；兜底仍失败则保留清理意图，
不得宣称已完整注销。真实传输恢复和后续实体迁移在各自版本继续实现。

注销先退休会话并删除凭据，再清理已登记各缓存根内该完整账号的数据。缓存盘不可用时保留注销意图，
显式注销/遗忘报告清理未完成；其他账号仍可连接，后续待办继续处理。同一账号的待办完成前
禁止写回凭据，避免失败重连复活已注销登录。成功清理后才移除对应根登记；仅清理未使用缓存
不会移除登记，因为仍可能有活跃资源。旧根探测和管理 I/O 不持有设置共享锁；关闭服务等待已接受操作排空。

从 0.2.1 升级时，显式缓存初始化为本地已知账号登记可信的当前根，补齐未打开媒体就清理/注销的旅程。
普通缓存登记拒绝待注销账号；仅内部清理登记允许已持久注销意图的账号。
0.2.1 已切走且没有记录位置的历史根无法可靠推断，不能通过扫描任意磁盘冒充完整清理。
