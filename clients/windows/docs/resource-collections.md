# 收藏、标签与浏览偏好

Windows 直接使用既有 `/api/favorites`、收藏分组与 `/api/tags` 接口，数据属于服务端当前用户，
不创建另一套本地收藏数据库。新增、编辑、移除和关联使用现有私有 Host request 通道。

## 资源身份与权限

- 显示名称和 `path` 不能替代原始 `wirePath`。`pathVerified=false` 的历史记录仍展示，但不允许打开或按路径解绑。
- 当前端返回 `pathRefs` 时，它是标签资源身份的权威来源；不能按显示路径合并两个不同原始资源。
- 旧端仅提供可信 literal UTF-8 路径时，逐段编码一次；不 URI 解码显示路径，不把 U+FFFD 猜成其他文件。
- 新增收藏或标签关联发送原始 wirePath；严格 UTF-8 可在同一次请求携带兼容 path。未知旧端的 opaque 路径写入保守拒绝，不自动改用显示别名重试。
- 元数据管理不套用文件 Create/Rename/Delete 权限。新增资源关联仍由服务端检查访问规则与存在性；记录 ID 管理、可信关联解绑支持遗失文件清理。
- 所有结果绑定 AccountKey 与活动会话。打开前重新取得资源元数据并核对原始字节身份；403、404、无法确认身份分别展示。

## 写入确认

HTTP 200 必须有与操作相符的确认结果；202、错误主体、失联和发送后的服务端错误不会伪装成完成。
结果未知时提示刷新核实并阻止直接重发；无唯一约束的分组/标签创建不能仅凭同名记录猜测本次成功。
已确认的 ACK 不因后续续期或刷新失败被丢弃。跨重启的通用操作核实记录仍属于后续待完成工作。

## 呈现与偏好

收藏和带色点的标签承担侧栏快速导航，独立管理入口承担分组、改名、颜色和关联管理。
标签颜色以实际色点表达，保留名称、关联数和文字状态；不只靠颜色传递状态。

浏览布局沿 Web 的拼贴、紧凑网格、Windows 图标、详细列表、紧凑列表。
紧凑网格与 Windows 图标分别保存小/中/大/超大尺寸；当前目录类型筛选与服务器搜索分开。
目录偏好由 `IBrowserPreferencesService` 保存至 schema 4，后台执行并绑定账号和原始目录身份。
本地应用布局不等待磁盘写入；失败要说明本次已应用但尚未保存。标签关联结果不是远端目录，不能伪造目录路径写入偏好。
